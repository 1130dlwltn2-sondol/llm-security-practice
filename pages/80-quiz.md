9. Grok에서 발생한 사건은 무엇인가?
   (1) 무단 시스템 프롬프트 변경 (2) 벡터 DB 탈취 (3) MCP 서버 오프라인 (4) 학습 데이터 포이즈닝

    (1) 최소 권한 (2) JSON 인코딩 (3) 허위정보 대응 (4) 무제한 소비

20. (단답형) 레드티밍 보고서 한 건에 반드시 포함되어야 하는 네 가지 구성 요소를 쓰시오.

## 해설

1. 정답: (2)
   LLM01은 프롬프트 인젝션이다. OWASP LLM Top 10 2026의 첫 번째 항목으로, 사용자 입력이나 외부 콘텐츠에 숨겨진 지시로 모델의 동작을 조작하는 공격을 다룬다. 이 책 전체에서 가장 자주 등장하는 위협이기도 하다.

2. 정답: (2)
   LLM03 과도한 에이전시는 2025년판 6위에서 2026년판 3위로 올라갔다. 에이전트가 도구를 직접 실행하는 구조가 확산되면서, 권한 남용의 위험도가 재평가된 결과다. 에이전트를 설계할 때는 도구의 최소 권한이 핵심 방어가 된다.

3. 정답: (2)
   LLM06 무제한 소비는 2025년판 10위에서 2026년판 6위로 올라갔다. API 비용 폭증과 서비스 마비를 노리는 공격이 현실적인 위협으로 자리 잡았다는 뜻이다. 요청량 제한과 토큰 사용량 모니터링이 기본 대응이다.

4. 정답: (4)
   LLM10 부적절한 출력 처리는 2025년판 5위에서 2026년판 10위로 내려갔다. 순위가 내려갔다고 해서 위험이 사라진 것은 아니다. 모델 출력을 검증 없이 하위 시스템에 전달하는 지점은 여전히 흔한 실수다.

5. 정답: (1)
   LLM08은 구 System Prompt Leakage에서 히든 컨텍스트 노출로 개명·확장되었다. 시스템 프롬프트 유출을 넘어 내부 규칙과 숨겨진 컨텍스트 전반의 노출을 다루게 되었다. "시스템 프롬프트를 보여줘" 같은 요청에 대한 방어 테스트가 대표적이다.

6. 정답: (2)
   EchoLeak은 Microsoft 365 Copilot을 노린 간접 인젝션 사건으로 CVE-2025-32711이 부여되었다. 공격자는 메일박스·OneDrive·SharePoint의 데이터 유출을 시도했다. 문서나 이메일에 숨겨진 지시가 Copilot을 통해 실행될 수 있다는 점을 보여 준 대표 사례다.

7. 정답: (2)
   DeepSeek에서는 인증 없는 ClickHouse DB가 노출되어 100만 건 이상의 평문 로그가 유출되었다. 모델 자체의 취약점이 아니라 운영 인프라의 설정 실수였다. 아무리 모델이 안전해도 데이터베이스 인증을 빠뜨리면 무너진다는 교훈을 준다.

8. 정답: (2)
   Amazon Q 사건(CVE-2025-8217)은 공급망 오염이다. 오염된 확장 기능이나 구성 요소가 배포 경로를 통해 유입되는 유형이다. 사용하는 모델·라이브러리·MCP 서버의 출처와 버전을 목록으로 관리하는 것이 기본 방어다.

9. 정답: (1)
   Grok에서는 시스템 프롬프트가 무단으로 변경되는 사건이 있었다. 시스템 프롬프트는 모델 동작의 기준선이므로, 변경되면 모든 방어 지침이 함께 흔들린다. 시스템 프롬프트의 변경 이력 관리와 무결성 검증이 필요한 이유다.

10. 정답: (2)
    Invariant Labs는 GitHub MCP를 경유해 프라이빗 리포지토리가 유출될 수 있음을 데모로 보여 주었다. MCP 서버가 제공하는 도구를 에이전트가 그대로 신뢰할 때 생기는 위험을 시연한 것이다. MCP 서버 출처 검증의 중요성을 보여 주는 사례다.

11. 정답: (2)
    Asana MCP 사건은 2025년 6월 4일에 발견된 실험적 MCP 서버의 연동 로직 결함이다. 테넌트 격리가 깨지면서 일부 사용자가 자신의 권한 범위 안에서 타 조직의 프로젝트·태스크·팀·댓글·파일을 조회할 수 있었다. 외부 침입이 아닌 내부 설계·구현 버그라는 점이 핵심이다.

12. 정답: (4)
    Asana는 약 2주간 MCP 서버를 오프라인으로 전환하고, 연동 로직을 패치한 뒤 모든 MCP 연결을 리셋하고 고객에게 재연결을 요구했다. 금전 보상 지급은 알려진 대응에 포함되지 않는다. 약 1,000개 고객이 영향을 받았을 가능성이 제기되었다.

13. 정답: (4)
    Anthropic 공식 6원칙은 tool_result 격리, 콘텐츠 성격·출처 명시, 시스템 프롬프트에 불신 정책 명시, JSON 인코딩, 자신의 지시를 tool_result에 넣지 않기, 최소 권한이다. 모델 가중치 암호화는 6원칙에 포함되지 않는다.

14. 정답: (2)
    도구 실행 결과(tool_result) 안에 "이제 이렇게 행동하라"는 식의 지시가 들어 있으면, 모델이 그것을 자신의 지시로 착각할 수 있다. 이것이 간접 인젝션의 대표 경로다. 자신의 지시는 tool_result에 넣지 않고, tool_result는 데이터로만 취급하는 격리가 필요하다.

15. 정답: (1)
    NIST AI 600-1(Generative AI Profile)은 2024년 7월 26일에 최종 발행되었다. GAI 고유의 위험 13개와 개발자가 취할 수 있는 400개 이상의 조치를 정리하고 있다. 2026년 10월 현재 이를 대체하는 후속 프로필은 없다.

16. 정답: (4)
    NIST AI 600-1의 리스크 관리 프레임워크는 Governance, Map, Measure, Manage 네 단계다. Deploy는 포함되지 않는다. 레드팀 평가는 Measure 단계에, AI 인벤토리(AI-BOM)는 Map 단계에 대응한다.

17. 정답: (1)
    AI Agent Standards Initiative는 2026년 2월에 출범했으며 에이전트 보안과 아이덴티티를 중심으로 다룬다. NIST 문서도 OWASP 가이드도 아닌, 에이전트 시대의 표준을 만들기 위한 이니셔티브다.

18. 정답: (1)
    테넌트 격리는 모든 요청에 조직 ID를 강제로 포함시키고, 세션의 조직 ID와 일치하는지 검증하는 방식으로 지킨다. 검증 로직은 도구 호출을 감싸는 래퍼 한 곳에 두어 새 도구가 추가되어도 자동으로 적용되게 한다. Asana 사례가 보여 주듯 격리는 설정이 아니라 코드다.

19. 정답: (1)
    최소 권한의 가장 확실한 형태는 필요 없는 도구를 아예 연결하지 않는 것이다. 연결하지 않은 도구는 악용될 방법이 없다. 파괴적이거나 되돌릴 수 없는 동작은 사람의 승인을 거치게 하는 것도 최소 권한의 연장이다.

20. 정답: 재현 조건, 영향도, 근본 원인, 개선안
    재현 조건은 어떤 입력으로 어떤 순서로 공격이 성공하는지의 단계별 기술이다. 영향도는 성공 시 노출되는 데이터나 실행되는 행동의 범위다. 근본 원인은 어떤 계층의 검증이 빠졌는지에 대한 분석이다. 개선안은 Part 3의 방어 중 무엇을 적용할지를 구체적으로 적은 것이다.
