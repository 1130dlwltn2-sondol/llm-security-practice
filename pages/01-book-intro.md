# 01. 책 소개

이 책을 쓴 이유부터 말하자.

2023년에 챗봇을 만들던 개발자는 한 가지 질문에 답하면 됐다. 모델이 잘 대답하는가? 2026년의 개발자가 답해야 할 질문은 두 개가 됐다. 모델이 잘 대답하는가, 그리고 모델이 시키지 않은 일을 하고 있지는 않은가?

차이는 에이전트다. 예전의 LLM 앱은 입력이 들어오면 텍스트를 뱉는 수동적인 프로그램이었다. 지금의 LLM 앱은 도구(function call, MCP 서버, 브라우저, 셸)를 들고 다니며 이메일 읽고, 파일 지우고, 돈 보내고, 코드를 실행한다. 자율성이 올라간 만큼 공격자의 상상력도 커졌다. 사용자 프롬프트 한 줄로 데이터베이스를 털거나, 에이전트가 외부 문서를 읽다 악성 지시를 받아들여 파일을 통째로 외부로 보내는 사고가 실제로 보고되고 있다.

그래서 '만드는 법'만큼 '지키는 법'을 배워야 하는 시점이 됐다. 이 책은 바로 그 지점을 다룬다. LLM 앱을 만들고 운영하는 개발자가 실무에서 바로 적용할 수 있는 방어 기술을, 세계에서 가장 널리 쓰이는 위험 목록인 OWASP LLM Top 10 2026을 기준으로 정리했다.

## 이 책에서 다루는 것

Part 1에서는 왜 지금 LLM 보안인지, OWASP LLM Top 10 2026의 10개 항목이 무엇인지, 그리고 LLM 앱에 대한 위협 모델링을 어떻게 시작하는지를 다룬다. 보안의 관점을 갖추는 것이 목표다.

Part 2는 이 책의 본론이다. OWASP LLM Top 10 2026의 10개 항목을 한 장씩, 공격 방식-실제 영향-방어 구현 순서로 설명한다. 각 장은 코드로 따라 할 수 있는 예제를 포함한다. 복사해서 바로 돌려볼 수 있는 수준으로 썼다.

Part 3은 방어 아키텍처다. 입력 검증과 출력 검증, 가드레일 설계, 도구의 최소 권한 스코핑, 사람 승인(휴먼인더루프) 설계를 다룬다. Part 2가 '각 위험을 어떻게 막는가'라면, Part 3은 '안전한 시스템 전체를 어떻게 설계하는가'에 대한 답이다.

Part 4는 레드티밍이다. 스스로 자신의 LLM 앱을 공격해보는 방법론, 배포 전 체크리스트, 그리고 MCP 서버 보안 실전을 다룬다. 마지막으로 사내 문서 도우미 에이전트를 안전하게 만드는 실전 프로젝트로 모든 내용을 종합하고, 확인 문제로 배운 것을 점검한다.

## 이 책에서 다루지 않는 것

정직하게 경계를 그어두자. 이 책은 모델 학습 이론을 다루지 않는다. 파운데이션 모델을 처음부터 학습시키는 법이나 파인튜닝 최적화에 대한 내용은 없다. 이 책의 독자는 모델을 쓰는 개발자지, 모델을 만드는 연구자가 아니기 때문이다.

심층 암호학도 다루지 않는다. 암호화 알고리즘의 수학적 증명이나 TLS 핸드셰이크의 내부 동작 같은 주제는 훌륭한 주제지만, 이 책의 범위를 벗어난다. 필요한 부분에서는 '무엇을 써야 하는지' 수준으로만 정리한다.

이 두 분야는 초급자의 진입 장벽이 높은 주제다. 이 책은 그 대신, 개발자가 오늘 당장 코드에 적용할 수 있는 방어 기술에 집중한다.

## 대상 독자

LLM 앱을 만들거나 운영하려는 개발자다. 챗봇, RAG 검색, 문서 요약 도구, 사내 에이전트 중 하나라도 만들고 있다면 이 책의 독자다. 보안 전문가는 아니어도 된다. HTTP와 JSON을 다룰 줄 알고, 간단한 API 서버를 만들어본 경험 정도면 충분하다.

## 이 책의 집필 원칙

이 책은 세 가지 원칙으로 썼다.

첫째, 실전 예제 중심이다. 개념 설명으로 끝나지 않고, 각 장마다 코드로 따라 할 수 있는 예제를 넣었다. 예제는 복사해서 바로 실행할 수 있는 수준으로 썼고, 실행에 필요한 준비물은 각 장의 앞부분에 명시했다.

둘째, 비밀값은 전부 더미 값이다. 예제에 등장하는 API 키는 sk-dummy-0000 같은 형태다. 실제 키 형태의 값이 예제에 섞여 있으면 독자가 그대로 복사해 쓰는 사고가 생긴다. 이 책에서는 그런 일을 원천적으로 막기 위해 모든 비밀값을 명백한 더미로 표기했다.

## 준비물

이 책의 예제를 따라 하려면 다음이 필요하다.

- Python 3.10 이상. 예제 코드는 전부 Python으로 작성했다. 특별한 라이브러리 없이 표준 라이브러리만으로 동작하는 예제가 대부분이다. 외부 라이브러리가 필요한 장에서는 해당 장의 앞부분에 설치 방법을 적었다.
- 텍스트 편집기와 터미널. 예제는 파일로 저장해 실행하는 방식이다.
- LLM API 접근 수단(선택). 일부 장에서는 실제 모델 호출 예제가 나온다. OpenAI 호환 엔드포인트라면 어디든 쓸 수 있고, API 키 자리는 전부 더미 값으로 표기했으니 자신의 키로 바꿔 넣으면 된다. API를 쓰기 싫다면 로컬 모델(예: Ollama)로 대체해도 된다. API 호출이 필수가 아닌 장에서는 모델 호출을 흉내 내는 스텁 코드를 제공한다.

## 각 Part 미리보기

Part 1은 관점을 만든다. 10장에서 왜 지금 LLM 보안이 중요한지를, 11장에서 OWASP LLM Top 10 2026의 전체 지형을, 12장에서 위협 모델링의 기초를 다룬다. Part 1을 마치면 "우리 앱의 위험 지도가 어떻게 생겼는가"를 말할 수 있게 된다.

Part 2는 각론이다. 20장부터 29장까지 OWASP LLM Top 10 2026의 10개 항목을 다룬다. 각 장의 구성은 동일하다. 공격이 어떻게 동작하는지, 실제로 어떤 피해로 이어지는지, 그리고 코드로 어떻게 막는지다. 이 구성 덕분에 필요한 장만 골라 읽어도 된다.

Part 3은 설계다. 개별 공격을 막는 것을 넘어, 안전한 시스템 전체를 어떻게 설계하는지를 다룬다. 입력 검증과 출력 검증(30장), 가드레일(31장), 도구의 최소 권한 스코핑(32장), 사람 승인 설계(33장)가 순서대로 쌓인다. 33장까지 마치면 방어 아키텍처의 청사진이 완성된다.

Part 4는 검증이다. 40장에서 레드티밍 방법론을 배우고, 41장의 체크리스트로 배포 전 점검을 하고, 42장에서 MCP 서버 보안 실전을 다룬다. 70장의 실전 프로젝트에서는 사내 문서 도우미 에이전트를 처음부터 안전하게 만드는 과정을 통째로 따라 한다. 80장의 확인 문제로 배운 것을 점검하고, 81장에서 마무리한다.

## 이 책의 코드 표기 규칙

예제 코드에는 몇 가지 약속이 있다.

- 비밀값, 토큰, API 키는 전부 sk-dummy-0000 같은 더미 값을 쓴다. 실제 값처럼 보이는 문자열은 절대 등장하지 않는다.
- 공격 예제는 주석으로 "공격 예제 - 실습 환경에서만 실행"을 명시한다. 공격 코드를 방어 코드와 헷갈리지 않게 하기 위해서다.

## 이 책을 읽기 전에: 선수 지식

이 책을 읽는 데 보안 전문가 수준의 배경지식은 필요 없다. 다만 아래 세 가지는 알고 있으면 좋다.

- HTTP와 JSON. LLM API 호출이 대부분 HTTP+JSON 형태이기 때문이다. 예제 코드에서 requests 호출이 나오면 바로 이해할 수 있다.
- Python 기초. 함수 정의, 딕셔너리, 리스트 컴프리헨션 정도면 충분하다.
- 간단한 API 서버 경험. Flask나 FastAPI로 "Hello, World" 수준의 엔드포인트를 만들어본 경험이면 된다.

암호학, 네트워크 보안, 침투 테스트 경험은 없어도 된다. 필요한 개념은 각 장에서 그때그때 설명한다.

## 이 책에서 자주 쓰는 용어

이 책에서 반복해서 나오는 용어를 미리 정리한다.

- 프롬프트 인젝션: 모델에게 악성 지시를 주입해 의도하지 않은 행동을 유도하는 공격. 20장에서 자세히 다룬다.
- 컨텍스트: 모델에게 입력으로 들어가는 전체 텍스트. 시스템 프롬프트, 사용자 질문, 검색된 문서, 도구 결과가 모두 합쳐진다.
- 가드레일: 모델의 입력이나 출력을 검사해 정책에 어긋나는 내용을 걸러내는 안전장치. 31장에서 설계 방법을 다룬다.
- 에이전트: 도구를 사용해 실제 행동(파일 읽기, API 호출, 이메일 발송 등)을 수행하는 LLM 앱.
- RAG: 검색 증강 생성. 외부 문서를 검색해 컨텍스트에 넣고 답변을 만드는 방식.
- 레드티밍: 자신의 시스템을 공격자 입장에서 테스트하는 활동. 40장에서 방법론을 다룬다.
- 신뢰 경계: 믿을 수 있는 데이터와 믿을 수 없는 데이터를 나누는 선. 12장에서 자세히 다룬다.

- 12장을 마치면: 자신의 LLM 앱에 대한 위협 모델(자산, 신뢰 경계, 공격 표면)을 그릴 수 있다.

- 30~33장을 마치면: 안전한 LLM 앱의 전체 방어 아키텍처를 설계할 수 있다.
- 40~42장을 마치면: 자신의 앱에 레드팀 테스트를 수행하고, 결과를 체크리스트로 정리할 수 있다.

Q. 보안 지식이 전혀 없어도 읽을 수 있나?
A. 그렇다. 이 책은 보안 전문가가 아닌 개발자를 대상으로 썼다. 필요한 보안 개념은 각 장에서 설명한다.

Q. 모델을 직접 학습시키는 내용인가?
A. 아니다. 파운데이션 모델을 학습시키거나 파인튜닝하는 방법은 다루지 않는다. 이미 만들어진 모델을 앱에 붙여 쓰는 개발자를 위한 책이다.

Q. 특정 벤더의 제품에 종속적인 내용인가?
A. 아니다. 예제는 특정 클라우드나 특정 모델 벤더에 종속되지 않게 썼다. OpenAI 호환 API라는 표현이 나오는 장에서는, 호환되는 어떤 엔드포인트로도 바꿔 쓸 수 있다.

Q. 공격 코드를 배우면 악용될 위험은 없나?
A. 이 책의 공격 예제는 방어 방법을 이해하기 위한 최소한의 수준으로만 다룬다. 모든 공격 기법은 학습과 방어 목적이며, 허가되지 않은 시스템에 대한 공격 시도는 절대 하지 말아야 한다. 첫 페이지의 주의 문구를 다시 한번 읽어보자.

Q. 2026년판 이후 OWASP 목록이 바뀌면 이 책은 낡은 것 아닌가?
A. 목록의 항목명과 순위는 바뀔 수 있지만, 이 책이 가르치는 사고방식(위협 모델링, 신뢰 경계, 최소 권한, 방어 아키텍처)은 목록이 바뀌어도 유효하다. 목록 개정 시에는 저장소의 정오표로 변경점을 안내한다.
